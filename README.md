# Samuel Kyere Portfolio

A statically exported Next.js portfolio for a software and integration engineer. The repository uses two Git worktrees: a source workspace for development and a generated workspace for GitHub Pages deployment.

## Workspaces and branches

| Purpose | Directory | Branch | What belongs there |
| --- | --- | --- | --- |
| Development | `/home/admirer/new_portfolio` | `master` | Source code, static assets, configuration, and documentation |
| Deployment | `/home/admirer/new_portfolio-pages` | `gh-pages` | Generated static files served by GitHub Pages |

Make changes only in the development workspace. The deployment workspace is generated by `deploy.sh`; do not edit its HTML, JavaScript, CSS, or assets manually.

## Prerequisites

- Node.js and npm
- Git, with access to push to `origin`
- `rsync` (used by the deployment script)

Install dependencies once in the development workspace:

```bash
cd /home/admirer/new_portfolio
npm ci
```

## Run locally

From the development workspace:

```bash
cd /home/admirer/new_portfolio
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

The local server intentionally runs without the GitHub Pages `/newPortfolio` prefix so files in `public/` load at paths such as `/project3.png`. The production build automatically uses `/newPortfolio` instead.

Stop the server with `Ctrl+C`.

## Make a portfolio change

1. Work from `/home/admirer/new_portfolio` on `master`.
2. Edit the page in `app/page.tsx`.
3. Put local images, SVGs, PDFs, and other static assets in `public/`.
4. Reference a public asset using the `BASE_PATH` helper where needed, for example:

   ```tsx
   const preview = `${BASE_PATH}/project3.png`;
   ```

5. Review locally with `npm run dev`.
6. Create a production export to validate the change:

   ```bash
   npm run build
   ```

7. Commit the source changes on `master` and push them:

   ```bash
   git add app/page.tsx public/ README.md
   git commit -m "Describe the portfolio change"
   git push origin master
   ```

Use `git status` before committing so you only stage the intended files.

## Deploy to GitHub Pages

The deployment script builds the site, copies the exported files to the `gh-pages` worktree, creates a deployment commit, and pushes it.

Before deploying, both worktrees must be clean:

```bash
git -C /home/admirer/new_portfolio status --short
git -C /home/admirer/new_portfolio-pages status --short
```

Then run:

```bash
cd /home/admirer/new_portfolio
./deploy.sh
```

The script will:

1. Confirm the development worktree is on `master` and has no uncommitted changes.
2. Run `npm run build` and verify the static `out/` folder.
3. Confirm the deployment worktree is on `gh-pages` and is clean.
4. Synchronize `out/` into `/home/admirer/new_portfolio-pages`.
5. Commit the generated changes as `Deploy latest portfolio build`.
6. Push `gh-pages` to GitHub.

The live site is: https://admirerbrown.github.io/newPortfolio/

## Troubleshooting

- **Local page is a 404:** start the server from `/home/admirer/new_portfolio` and use `http://localhost:3000`.
- **Images fail locally:** keep the asset in `public/` and use its root path in development (the `BASE_PATH` helper handles the production prefix).
- **`deploy.sh` stops because `gh-pages` is dirty:** inspect the deployment workspace with `git -C /home/admirer/new_portfolio-pages status`. Preserve or move any intentional work back to `master`; deployment output should not be edited directly.
- **Build fails:** rerun `npm run build` from the development workspace and fix the reported TypeScript, Next.js, or asset-path error before deploying.

## Project structure

- `app/` — Next.js App Router page, layout, and global styles
- `public/` — static assets included in the export
- `next.config.js` — static-export and environment-specific base-path configuration
- `deploy.sh` — guarded build-and-publish workflow for `gh-pages`
- `out/` — generated static build output (created by `npm run build`)
